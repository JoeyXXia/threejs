## 反例与修正

- 本机没有 Docker / PostgreSQL 工具。保留 Compose，改用 npm 提供的便携 PostgreSQL 验证，未安装系统服务。
- `initdb` 在仓库中文路径中报告 UTF8 编码错误；只移动数据目录仍然失败。最终把原 npm native 二进制树复制到 ASCII TEMP 缓存，使用 pg_ctl 启停，数据也置于 TEMP。首次适配中还修正了密码文件不能放入待初始化数据目录、建库接口不能依赖原库的进程句柄两个问题。
- Jest CJS loader 无法直接加载 Nest 12 ESM；没有新增转译框架，改为启动实际构建 API，通过 HTTP 测试。tsx 开发入口另由 smoke 验证；显式 `@Inject` 避免依赖 tsx 不生成的参数元数据。
- pnpm 运行时从 Day 1 的 24.19 更新到 24.22.1，原 engines 过窄导致安装失败；保留应用 Node 22.14.0，允许包管理器使用 24.19 以上 24.x。
- 包管理器自动追加待决构建脚本条目曾与手工配置重复；清理重复配置，并对未使用的可选构建脚本显式标为 false 后安装通过。

这些失败均发生在实际命令执行中；没有把失败尝试记为通过。

## 状态权威、事务与 UI

PostgreSQL 保存用户、会话摘要、空间、仓库和访问关系。操作者从会话取得，不能由 body 选择。访问角色每次从 DB 读取；写事务共享锁定访问关系，再进行角色检查、版本条件更新与审计。故意让审计插入失败的测试验证资料更新回滚。

前端仅保存显示身份和表单状态，Cookie 不写 localStorage。到期定时清理与 HTTP 401 处理已实现；响应采用代次检查，避免旧身份请求覆盖后续状态。浏览器交互和显示定时器未进行端到端验收，不将 HTTP 测试等同于这些 UI 行为已验证。
