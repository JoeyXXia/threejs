# Day 08：入库、批次与质检

实际日期：2026-11-05（Asia/Shanghai）。基线 `6b8c5e7 / v0.1-scene`；本日志记录 Day 8 提交前的实现与验收结果。

- 范围：一单单 SKU/批次、全量幂等收货到 QC/HOLD、一次通过或拒绝质检。复用 React/Query、NestJS/Prisma/PostgreSQL，不增加框架、服务或机器人控制。
- 改动 1：InboundOrder 与批次生产日期，两条追加迁移；RECEIPT 与 seed OPENING 分开；数量、阶段字段、归属、收货质量和日期受约束。
- 改动 2：入库读取/创建/收货/质检 API；事务内授权、仓库/单据/货位锁；业务、余额、流水、审计、成功幂等结果一起提交；阶段键防不同 key/操作者重复过账。
- 改动 3：独立入库路由、创建/收货/质检表单、只读与错误提示；成功精确失效 Query，库存不放进 Zustand；同页面原参数的未知结果重试复用 key。
- 前端验证：6 文件、39 项通过；lint、strict typecheck、build 通过。共享契约解析、幂等 key 保留与参数变化、错误数量/日期/身份字段、跨仓响应均有覆盖。
- 真实数据库验证：3 suites、64 项通过（原授权 18、库存 26、入库新增 20）；重复与并发、不同 key/操作者、同批多单、过期、容量竞争、约束、审计/流水故障回滚、撤权和 API 重启均覆盖；两个库重启后余额/流水对账差异 0。
- 浏览器：真实表单操作；后端已提交后截断响应，再用原参数重试，只入账一次。3 件通过 + 2 件过期拒绝，汇总从 62/55/0/7 到 67/58/0/9（现存/可用/预占/HOLD）；整页刷新、3D 与 2D 批次详情一致。B 仓 viewer 输入/按钮禁用，列表不串仓。
- 会话边界：QA 实际使会话过期，刷新入库单后返回登录并清除旧订单及操作表单。
- 实际失败：批次模型无默认 id，首轮 typecheck 发现后补 UUID；初轮测试夹具增加仓库导致旧授权 3 项失败，改独立测试库而不放宽断言；新库名称含数字被已有便携库校验拒绝，改为纯字母/下划线；浏览器先误用 fieldset.isDisabled，改查实际按钮和输入后通过。
- 收尾：显式对齐新表外键 onUpdate=NoAction；Prisma generate 曾因本次 QA 持有 Windows DLL 失败，关闭测试服务后重试通过。报告链接检查 36 项通过，历史 PDF 归档哈希不变。
- 限制：没有部分收货、质检撤销、退货、业务预占、任务运输、实时事件或生产部署；入库列表最多 100 单；日期采用 UTC 零点；未测性能。既有 PDF 历史版本保持原样，按每周规则更新。
- AI 协作：AI 辅助实现与测试、报告；用户独立口述事务与幂等仍需另行验收，不替用户宣称已掌握。
