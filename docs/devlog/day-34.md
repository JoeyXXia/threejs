## 三组可独立审查的改动

1. **网关压缩与撤权**：`apps/api/src/realtime/telemetry.ts`、`warehouse.gateway.ts`、车队提交事件和共享契约。新版订阅显式启用 telemetry；每页保留连续 seq 与业务/告警，位姿最多一个最新样本。旧订阅和 HTTP 权威事件页保留原 payload。慢客户端仍仅一页在途；等 ACK 期间继续重查会话/授权。
2. **前端采样与 mesh**：`useRealtimeSnapshot.ts`、`pose-buffer.ts`、`FleetModels.tsx`、`RobotModel.tsx`、场景接线。每种仓库实例一个最新样本槽；位姿消息不直接写 Query，只唤醒 R3F，整仓快照按位置降频，业务事件/告警/缺口立即同步。跨序号、布局、epoch、任务不匹配不应用。
3. **验收**：单槽与清理单测、真实 Socket 慢 ACK/撤权、Chrome 反复切仓和进出回放。见 [Day34 验收](../../reports/day-34-acceptance.md)。

## 权威与失效边界

PostgreSQL 已提交事件、库存和快照仍为权威；丢弃的是传输层旧位姿载荷，不是业务事件或序号。现场没有依赖 Redis 或新的状态框架。最易失败的是把跳帧平滑成一条没有确认的路径，或允许旧连接的缓冲跨仓库/回放存活；跳过多个 tick 时直接显示最后确认格，重建/撤权/卸载清空旧缓冲并清理计时器和监听。临时离线只保留一个最后确认样本，不继续移动或外推。

## 可观察验收

1. 慢客户端不 ACK 期间最多收到一页，每页最多一个位姿、保留连续业务序号；原始事件 HTTP 仍可重取。
2. 缓冲只保留 1 个样本，拒绝旧 seq/epoch、布局或任务不匹配；跳 tick 不外推。
3. React 快照提交次数与渲染侧可观察到的位姿 tick 分开；仓库切换、回放进出、重连后活动连接回到 1/0。
4. 慢客户端等待 ACK 时撤权仍断开；页面作用域卸载取消请求、监听与样本计时器。
