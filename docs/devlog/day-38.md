## 权威与最易失败的边界

PostgreSQL 已提交余额、业务流水、货物归属和事件水位是权威；不是 HTTP 状态码、JS 回调完成或画面所示。最难区分的是 SQL 已执行与事务已提交：领跑事务执行完实际业务写入后停在提交前；另一个连接实际阻塞由 `pg_blocking_pids` 证明。发运用例故意在流水、状态、事件、幂等记录和日报待办都曾写入后抛错；每轮的对手都要在回滚后接着提交，且不能看到半成品。

每轮核对库存/预占对账及连续事件水位。`T04` 额外检查已装货的有效任务和在途余额匹配，故障后禁止旧提案推进并由原任务续跑。没有变更产品锁策略，不推进 Day39。
