## 当前实现与最小修改

Day 18 的任务在内存，库存事务与内存发布之间有窗口。Day 19 拆为三组审查：

1. **模型与统一边界**：Prisma runtime/event 迁移、`warehouse-state.ts`；入库、出库、盘点、运输、仓库资料写入取得统一提交锁并追加域事件。
2. **持久运行与读取**：SimulationService 从检查点恢复，按数据库 lease/epoch、expectedTick/version 提交；运输提取事务内组合入口；模拟和库存快照带水位，新增授权事件读取；页面显示水位/epoch。
3. **验证与报告**：扩展真实库测试，新增检查点/事件契约单测、无损升级夹具、真实 API 进程重启证据、数据库重启事件对账和浏览器回调；记录 ADR 0011、报告及截图。

## 五个可观察验收条件

1. 两个独立数据库客户端的 runner 不能同时取得有效写权，过期接管递增 epoch，旧计算被拒。
2. 重复 expectedTick 或 WMS 写入改变 version 后，旧提案不能覆盖检查点。
3. 事件写入失败时，库存、任务、审计、检查点和 seq 一起回滚；重试不留序号空洞。
4. API 真正停止/重启后，任务 ID 和已提交 tick 保留，从下一 tick 继续，而不按墙钟跳到结束。
5. 三个隔离库重启后库存/预占/事件/检查点无差异，页面刷新后的水位与完成态 API 一致。

## 状态与事务边界

PostgreSQL 保存库存和运行状态权威。锁顺序固定为访问关系、Warehouse、WarehouseRuntime，再到单据/货位/余额。A* 和纯 tick 提案在事务外计算，提交时复查状态版本、布局和 fencing。取放效果、检查点和事件共用事务，关闭 Day 18 的提交后内存发布窗口。Query 只缓存，Zustand 仅 UI，R3F 不推进业务。设计详见 [ADR 0011](../adr/0011-persistent-runtime-and-events.md)。

## 失败与修正

第一次真实库运行失败：TypeScript 的结构类型允许带 actorId 的 scope 传给公共锁函数，而对象展开把 actorId 写进 runtime。改为显式选择 spaceId/warehouseId，事件写入也做相同处理，再跑真实库通过。没有跳过失败测试或放宽数据库验证。

之前保留的取放失败注入改为事务内组合入口，继续验证停止时载货/账本不误变。增加旧 epoch、旧 tick、WMS 版本变化、事件失败回滚、慢事务租约过期、事件分页和跨仓游标测试。原始 JSON/TAP 只保留本地和 CI 产物，不上传临时库信息。
