## 与 v0.2-wms 的区别

- 布局可转换为地面导航网格；有界 A* 找到货位的地面服务点路径，而不是穿过货架到货位几何中心。
- 独立 TypeScript 单车核心使用离散 tick、显式 seed 和固定加载/卸载步骤；Nest runner 提交运动与任务阶段，浏览器只显示确认轨迹。
- PostgreSQL 持久检查点、owner lease/epoch 和 tick/version fencing 支持进程重启后从已提交状态续跑；流水、载荷、任务和事件同事务，不因动画完成扣货。
- QC RELEASED 整单经虚拟 TRANSIT 上架到 STORAGE，来源数量/目标容量同时预占；落货后成为可用于出库分配的库存。出库搬运到暂存后保留预占，操作员发运才扣全仓现存。
- Day 21 将这些已实现能力串为可复现录像，逐阶段查货、核对事件和最终账实，不添加额外框架。

## 一笔货如何流转：演示讲解

1. 创建一单新批次 4 件不改库存；收货后 4 件在 QC-01/HOLD，全仓从 62 变 66。
2. 质检通过将这 4 件改为 RELEASED，仍在 QC，不是上架，不增加全仓数量。
3. 启动上架：预占 QC 来源及目标储位容量。APPROACH/LOADING 时货还在 QC；取货提交后才在虚拟 TRANSIT，数量与预占都是 4。UNLOADING 期间仍在车上；落货提交后在 R02-3-L1，4 件不再预占。地面机器人不会真实举升到货架层。
4. 对同一批次创建出库单并全量分配。出库 APPROACH/LOADING 时货在储位，取货后在本任务 TRANSIT，卸货后在 OUT-01，始终保留 4 件订单预占。库内搬运全仓仍为 66。
5. 操作员确认整单发运，货从 OUT-01 到外部，新增唯一 DISPATCH 流水，全仓才回到 62。新批次的 7 条流水包含收货 1、质量变更 1、两次搬运的取/放各 2、发运 1；最终对账为零差异。

录像中约 13 秒展示上架 TRANSIT，约 24 秒展示出库 TRANSIT，约 29 秒展示到齐但未发运，约 35 秒展示最终对账。精确证据以报告记录的快照、水位及文件为准，不把截图采集时间当作事务提交时间。

## 复现与升级

按 [README](../../README.md) 启动本地应用；已有 Day 20 数据库无需新增迁移。新环境仍按现有迁移流程安装，禁止 reset 已有业务库。

录像使用普通隔离 QA seed 与测试账户，不使用开发库、秘密或手改库存。步骤和录像命令见 [浏览器验收说明](../../scripts/browser-checks/README.md)。`pnpm check`、`pnpm test:unit`、`pnpm test:integration` 可复验，原始 JSON/TAP 留本地，报告保留测量摘要。

## 发布边界

版本通过 Git 注释标签 `v0.3-single-robot` 与本发布说明归档；不代表创建了额外 GitHub Release 对象、部署到服务器或发布 npm 包。main 与标签在推送后核对，提交链接见本轮交付回复。

仍为单仓单车软件模拟、250ms 轮询；无多车避碰/拥堵协调、Socket 推送、产品级暂停/历史回放、取消/异常恢复操作台、自动充电或真实设备。视频暂停和测试停步只用于查证状态，不冒充这些后续能力。测试包括真实进程/数据库重启，不等于生产 SLA 或任意崩溃点证明；无本轮应用 FPS、吞吐或生产并发承诺。
