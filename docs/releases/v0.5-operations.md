# v0.5-operations

WarehouseTwin 第 5 周阶段：从实时仓库的任务和封路告警切换到独立的只读回放。只模拟软件车，不接真实设备。

[运营录像](../../reports/day-35-demo.webm) · [实测验收](../../reports/day-35-acceptance.md) · [复现步骤](../../scripts/browser-checks/README.md#day-35--运营回放录像)

## 给运营人员看的演练

1. 在实时仓库分配一笔出库搬运。记下 `robot-2` 和账本任务编号（与车队认领号并列）。搬到暂存不等于发运。
2. 暂存入口被封锁，车显示 `NO_PATH` 并暂停。不要反复点分配；同一任务留在原车上。
3. 浏览器离线时留着**最后确认快照**，操作不可提交。独立在线测试端解封并新增预占。连接恢复后，以新确认的库存和任务状态为准。
4. 打开**历史回放**、选择原任务并拖动时间轴。归档布局、当时库存和封路修订来自历史，不随当前仓库改变。要看当前库存，点「返回实时仓库」。

## 技术讲解

- 库存、任务、事件和用于回放的帧按已提交的仓库水位关联；实时差分中可丢弃过时位姿，但历史事件可补取。
- React Query 保留实时确认态，Zustand 管理历史时间轴的选择与播放；R3F/Drei 把确认态画出来，不推进仓库业务。
- v0.5 使用 Git 注释标签归档，不意味着部署、真实设备控制或性能 SLA。录像是一次本机隔离演练证据，不是持续可用性证明。
