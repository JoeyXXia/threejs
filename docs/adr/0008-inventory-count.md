# ADR 0008 单货位盘点与审批

日期为 2026-11-09。Day 11 基线为 `168e34f`。

## 盘点范围

首版开放当前布局中的储位与出库暂存位。盘点按货位快照中的余额行逐项记录实数，包括原有零余额行。空货位可提交空明细。账外 SKU 或批次通过录数说明记录，待明确归属后再处理。质检位涉及收货和待检单，在途位由运输任务管理。

盘点单的状态为 OPEN、SUBMITTED、APPROVED 或 REJECTED。OPEN 和 SUBMITTED 共同表示货位冻结，PostgreSQL 部分唯一索引限制每个货位只有一张活动盘点单。操作员和管理员可以开单和录数，批准或拒绝由仓库管理员执行。管理员可以批准自己发起的盘点。审批理由和操作者可从关联审计查询。

## 冻结与过账

盘点、出库分配和运输创建都在事务内取得仓库行锁。开盘检查所有余额的预占，以及原来源或目标关联的 READY / IN_TRANSIT 运输任务。货位即使没有余额行，只要存在活动运输也不能开盘。冻结货位从出库推荐和实际分配中排除，新的运输任务不能以它为暂存目标。数据库触发器同时保护直接余额写入和运输目标插入。

审批重新核对当前布局、完整余额集合和每行的身份、版本、数量及预占，再检查实数总量与储位混放规则。若出现布局、行集合或版本变化，单据保留冻结状态，由管理员拒绝后重新盘点。事务先将盘点标为批准，继而在仓库锁保护下更新余额、流水、审计和幂等响应。其他事务只会看到完整提交，任一步失败都恢复到提交前状态。先过账减少项，再过账增加项，避免中间状态临时超容。

每个非零差额产生一笔 `COUNT_ADJUSTMENT`。盘盈写货位为目标，盘亏写货位为来源，数量为差额绝对值。现有对账按流水有记录的一端计算数量，能直接复算两类调整。零差异只关闭单据并写审计。

## 读取与重试

数据库是盘点、库存、冻结和审计的权威。库存快照继续报告实物口径，冻结改变的是储存区可分配性。React Query 在盘点成功后刷新盘点、库存和出库推荐，Zustand 继续承载场景交互状态。相同操作者的相同请求键与参数可回放成功结果，改参返回冲突，审批在回放之前重新检查权限。
