# ADR 0010：单车阶段、事务效果与确认段显示

日期：2026-11-12（Asia/Shanghai）。状态：Day 18 采用。仅软件演示，不是机器人控制协议。

## 决定与范围

沿用 Day 17 的纯 TypeScript 状态和 A*，新增 `RobotTask`：`APPROACH → LOADING → TRANSPORT → UNLOADING → COMPLETED`。装载和卸载各等待 4 个逻辑 tick（默认共 1000ms），每个运动 tick 最多一格。错误进入 ERROR，禁止覆盖或自动重试。仅一台车、一次处理一条已预占 Allocation，整单多条分配需逐条启动。到齐暂存后本轮不自动 dispatch。

首任务从当前布局的 CHARGING 服务点出发，无该点则从取货服务点出发。后续任务沿用同布局最后位置及剩余电量。起点、取货点与目标均为合法地面服务点；不是架内货位坐标。新运行 seed=42、电量=10000 基点。开始前计算接近与运输两段 A*，两段都成功且移动耗电严格小于剩余电量才创建运输任务。没有实现充电或复杂电量调度。

## 状态权威与命令

- PostgreSQL 保存 Allocation、TransportTask、在途/实体余额、预占、流水和审计；既有库存权威不变。
- Nest `SimulationService` 暂时保存每仓单车的内存 tick、路线和显示阶段，是本阶段服务器模拟位置的来源。`GET simulation` 只是读取，不驱动任务；`POST simulation/start` 只接受分配、暂存位和原因，不接受操作者或前端完成通知。
- 每次读/启动复查仓库访问；viewer 可读、不能启动。启动身份来自会话。后台每个 tick 复查该启动人的仓库写权限；撤权后停止。登录会话到期只关闭 UI，不是取消已接受任务的命令。
- 相同 allocation/暂存目标的重试返回现有任务，不重置 tick；不同目标或仓库忙时返回冲突。该保护依赖单进程内存，不等价于 Day 8 的持久 key/hash 幂等结果。
- Query 按用户/空间/仓库缓存轮询结果；Zustand 继续只保存 UI。阶段变化触发对应库存、出库和台账查询失效，不每帧改库存，也不每个 tick 重取全量库存。

## 时钟和事务边界

模块生命周期只建立一个 250ms interval，所有仓库由同一串行驱动遍历。重入标志拒绝重叠回调，不按迟到的墙钟补跑历史 tick。一次回调处理慢时模拟变慢；没有做吞吐承诺，也没有新增队列框架。

纯 `stepRobotTask` 返回下一状态和可选 `take/drop` 效果提案，不自行碰数据库。服务在装载结束时调用 Day 10 `TransportService.take`，在卸载结束时调用 `drop`，成功后才替换内存快照。事务仍复用既有仓库锁、权限锁、余额/阶段/流水/审计原子提交及阶段唯一业务键。新增可选 expectedLayoutId，运行路径的布局必须在仓库锁内仍有效；旧调用方保持兼容。

取货把现存和预占从来源移到虚拟在途，卸货移到出库暂存；两次操作均不减少全仓现存。失败不发布提案中的新 tick、位置或载货状态，原位置停住并显示 ERROR。卸货失败保留上次确认的载货标记，不把仍在 TRANSIT 的库存误画为空载。

**尚未原子化的是数据库提交与内存发布。** 进程可能在 DB 成功后、内存更新前退出，或数据库返回结果不确定。此时不继续猜测；停止任务并保留数据库事实，留给 Day 19 的持久 checkpoint/owner/epoch/expectedTick 修复。当前严禁多 API 实例同时驱动同一仓库；不能以本地重入标志宣称已经有跨进程单 owner。

## 显示与陈旧状态

响应携带同布局下最后确认的 from/to、tick、logicalTimeMs、方向、路线、载货和电量。契约拒绝跨多格确认段及逻辑时间不一致。R3F `useFrame` 通过 mesh/material ref 更新，不逐帧 React setState。模型为简单盒体和方向标记，载货时增加货箱；Drei Line 绘制当前阶段路线。

收到新 task/tick/phase 才更新单调接收时间；重复轮询同一 tick 不重启插值。进度在 `[0,1]` 内，最多显示到已确认的 to，不向后续 route 点外推。超过 1500ms 没有新确认步时模型灰显，面板也提示陈旧；请求失败立即给出警告。`frameloop=demand` 只在需要插值/检查陈旧时主动 invalidate，结束后停止连续绘制。面板 500ms 定时器仅更新陈旧提示，不是第二套逻辑时钟。

Canvas 的 `data-robot-*` 是只读 QA 诊断，帮助核对实际渲染坐标和停滞；业务服务不读取 DOM。切仓卸载模型和查询，401 清除旧机器人控件与场景；布局身份不匹配时不绘制旧模型。

## 后续与限制

详见 [Day 18 报告](../../reports/day-18-acceptance.md)。本轮未增加数据库迁移、Socket、Redis、BullMQ、真实设备或多车协调。后端重启会丢失内存运行，已 IN_TRANSIT 的任务不能重新从头启动；该限制已测试，并在 UI/README 公开。模拟摘要仍是 Day 17 核心状态摘要，不把它当作包含任务阶段的持久检查点。
