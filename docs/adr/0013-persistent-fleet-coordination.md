# ADR 0013：持久多车归属与保守批次协调

日期：2026-11-17（Asia/Shanghai）；范围：Day 22。保持现有 React/R3F/Drei、Zustand/Query、NestJS/PostgreSQL；不新增调度框架、Socket、真实设备或 Day 23 通道许可。

## 最小决策与状态权威

复用单车纯 `RobotTask` 的路径、加载/卸载 phase 和取放效果提案。在其上增加纯 `FleetState` 和统一 `stepFleet`，但纯函数结果不是库存提交。PostgreSQL 的 `WarehouseRuntime.fleet` JSON 检查点、统一 tick/版本/seq、owner lease/epoch 和 `FleetClaim` 表共同构成权威；前端只读取确认轨迹，Query 缓存，Zustand 只保存场景 UI。

`FleetClaim` 永久保留仓库、领域任务 kind/id、领取车、原操作员、载荷标志与 active 状态。数据库按仓库/kind/task 唯一、active 的仓库/robot 部分唯一索引，防止任务双领和一车多个活动任务。触发器校验 scope 内领域阶段，拒绝删除或变更归属；完成 claim 不重新激活。纯快照历史的幂等检查只是补充，不能取代数据库约束。

## 初始车队与旧版本兼容

仅没有活动或异常单车任务时可显式初始化 3–5 台软件车。旧完成车辆的位置、电量、统一 tick 保留；若旧检查点属于不同布局则拒绝切换，不能静默传送或补满电量。其他车辆为合成初值，在当前布局选择不同、互不相邻的可走停车格。不是自动充电或物理停车资源许可。

旧单车检查点在未启用多车时原样保留、继续可用。显式切换时清空旧当前检查点，历史仍在已提交事件中；新多车模式禁止旧单车启动命令覆盖。已初始化车队不能重置、缩放或切回单车来丢弃载荷/异常。未知/损坏 JSON、时钟、路径、任务归属或占格校验失败时停止，不创建假初值。

## 分配与批次事务

1. 先授权并在写事务外按当前车位、布局版本算 A*。规划绕开已知其他车当前格和终点；取/放端点可排队。这只是一次静态规划，不是动态重规划或通道资源锁。
2. 写事务取得 actor ACL SHARE → Warehouse → WarehouseRuntime，重新检查版本、布局、电量和领域阶段。复用原取放领域服务创建任务/预占来源及容量，再原子创建唯一 claim、保存车队任务和事件。失败不留下新运输任务/虚拟货位。相同领域任务/同车重试返回既有 claim，不重置路线；不同车或目标冲突拒绝。
3. 全仓 runner 通过数据库 lease 和递增 epoch 取得写权。纯批次在事务外计算；提交固定顺序锁各原操作员 ACL，再锁仓库/runtime，核对 owner、epoch、expectedTick/version、布局、权限和账本阶段。
4. 批次内所有接受的车位/phase/载荷、claim、库存两端、原业务唯一流水、审计和统一事件一起提交，尾部再次检查原租约未过期。`proposalKey` 不替代既有库存唯一动作键。任何一步失败整批回滚，旧 owner/旧提案不能覆盖新提交。
5. 权限撤销、布局/账本异常或明确的过账异常保守停止活动批次，保留最后确认位置、在途货物与 claim。ERROR 车仍占格，不自动释放/重分配；恢复操作台属于后续范围。数据库不可用时不推进检查点。

## 冲突与等待政策

所有车都进入起始占格集合，包括 idle、完成、暂停与错误车。集中比较一步提案，禁止同格、edge swap，且保守禁止进入其他车本 tick 开始时占据的格，即使它本步准备离开。

相同空目标按固定 priority、连续等待 tick、稳定车 id 决胜。当前产品所有车同等初始 priority，不提供任意优先级配置接口。被拒只推进统一逻辑 tick，不推进路线游标、phase、库存或电量；记录原因、阻挡车、连续/累计等待。不能完成时保持真实等待，不将安全当作活性证明。

共享 QC 出入口和同一出库暂存服务点可能产生对向或停车阻挡；完成车不会变透明。测试同时覆盖并发真实等待、以及为避开该反例而顺序让三台车分别完成上架。**不承诺同一工作站上的并发任务全部完成、任意地图无死锁、全局最优或生产吞吐。** 不为了演示成功偷偷移动停车车、改库存或增加下一天的资源许可。

## 读取、对账与限制

授权接口为 `GET fleet`、`POST fleet/initialize`、`POST fleet/assign`，使用仓库 URL 前缀。多车快照包含 role、布局、水位/epoch、各车确认段、phase、任务/claim、载荷及等待。前端按用户/空间/仓库隔离 Query，R3F 插值只连接已提交相邻格，不外推；接口失败保留最后确认段并提示。viewer 仅读。

库存对账继续涵盖实物/虚拟余额、预占、在途和容量；新增 claim 与领域阶段、纯历史、当前 active 任务归属的检查。真实数据库重启验收同时核对旧单车及新车队检查点和末次事件 tick。纯历史当前有 10000 项上限，未测试长周期规模；无本轮应用 FPS、吞吐或生产并发结论。阶段验收见 Day 22 报告。
