# ADR 0014：单容量物理资源许可

日期：2026-11-18；范围：Day23。基线 Day22 `7810cce2e3664ea7c7a70d8fc73a367fed320fe2`，不做 Day24 封锁/重规划或真实设备控制。

## 方案、状态权威与兼容

沿用 React/R3F/Drei、Zustand/Query、NestJS/PostgreSQL。资源配置和 ownerId 存在既有 `WarehouseRuntime.fleet.state.resources` JSON 检查点，不新增框架、Redis、队列或数据库表。旧 Day22 JSON 无该字段表示未配置资源，仍受原占格协调；不是偷偷将整个仓库自动识别为通道。已启用车队后，操作员/管理员通过 `POST fleet/resources` 显式配置 AISLE/PARKING/CHARGING/WORKSTATION，viewer 拒绝。

每组容量固定 1，配置 1–32 组、每组 1–128 个连通且可走、不重叠的地面格。停车/充电/工作站同样是单容量格组，不代表已实现自动充电、升降或工站处理。首次须无活动任务；已有物理车所在组立即归该车，组内已有多车则拒绝。配置永久保留，相同规范化请求幂等，不能删除/更换配置重置异常许可。不提供任意动态地图编辑器。

## 请求、进入与释放边界

纯步进先验证资源 owner 与当前物理占格完全一致（无车则 null，1 车则其 id，不能有 2 车），损坏时 fail closed，不猜测或自动释放。按照原 priority→连续等待 tick→稳定 id 为入口提案申请许可。已在资源内的 owner 不受外侧等待者抢占；拒绝资源的目标先改为原地，再进行同格/edge-swap/起始占格协调，防止“没许可的外车赢顶点仲裁、堵住合法 owner 出清”的假死锁。新申请若随后因物理占格被拒绝，不持有悬空许可。

仅接受进入的同一批次设置 owner；组内移动持续持有；**真实提交到组外后**释放。出清当 tick 开始时仍持有，外车要下一 tick 才能进入，不在同 tick 转交。最终 owner 按接受后的物理占格重算，并与全车位/phase/库存效果/事件一起提交。空闲、完成、ERROR 或暂停车辆保持占格和许可；不以任务完成或租约过期替代物理出清。

`RESOURCE_BUSY` 携带 resourceWaitId、阻挡车、连续/累计等待 tick。该原因描述上一步决定，owner 可能在同批次末尾已出清；读契约不能错误要求它仍是当前 owner。等待不消耗电量、不推进路径/任务阶段或发出库存效果。对向、入口停车、跨资源循环仍可能无限等待，不承诺无死锁、公平或吞吐。

## 事务、并发与同步

配置与原命令同样 ACL SHARE→Warehouse→WarehouseRuntime，上锁后验证当前布局与检查点；配置/初始物理 owner 和 `FLEET_RESOURCES_CONFIGURED` 事件同事务。重复请求不增长水位，不绕过权限。

runner 使用原数据库时钟 owner lease/epoch、expectedTick/version fence，事务外纯计算，提交在原批次锁内；许可、位置、领域取放、claim、统一 tick/事件同生共死。runner 的 5 秒写权租约只决定哪个进程可提交，**不决定物理资源释放**。接管读取原 owner，无 TTL 清理；权限撤销/过账异常停止活动批次，资源和最后位置保留。失败事件导致所有许可/库存/车位回滚，不暴露临时 grant。

Query 读取授权的已提交资源表/等待；R3F 沿用确认段动画，不由浏览器授予或回收许可。`FLEET_TICK` 保存资源归属与等待原因。只读 WMS 对账增加许可/占格检查，真实数据库重启验收额外验证资源几何及 owner，不以客户端重建替代数据库重启。

## 最小验收与边界

纯反例覆盖两个不同空入口同时申请、原 owner 出清优先、出清后一 tick 才转交、错误/空闲/完成占格、非法/重叠/断开配置及序列化恢复。真实库覆盖授权/不可重置、双客户端读取/幂等、批次失败回滚、租约接管与旧提案拒绝、撤权 ERROR 保留、完成驻站及故意损坏对账。浏览器使用真实 UI 配置四类资源并观察五车等待，不要求全部并发任务完成。结果只写实际执行证据，见 Day23 验收报告。
