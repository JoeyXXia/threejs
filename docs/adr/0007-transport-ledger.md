# ADR 0007 搬运账本与暂存容量

日期 2026-11-08。基线为 Day 9 提交 `7b378f6`。本次用 Nest 内部服务和 PostgreSQL 集成用例完成单 SKU、指定批次的出库搬运。

## 状态和账本

每条原始 `Allocation` 最多创建一个 `TransportTask`。同一张出库单可以有多个来源储位，因此可以有多个任务。分配保留来源余额、货位、批次和件数。每个任务绑定一个独占的虚拟 `TRANSIT` 库位，代表该任务占用的模拟载货位。目标是当前布局中的 `OUTBOUND` 货位，样例使用 `OUT-01`。

| 操作 | 状态 | 现存与预占 | 目标容量 |
| --- | --- | --- | --- |
| 创建任务 | READY | 沿用 Day 9 来源预占，实物留在来源 | 预留分配件数 |
| take | IN_TRANSIT | 来源的现存和预占同步移入在途库位 | 保持预留 |
| drop | STAGED | 在途的现存和预占同步移入暂存位 | 预留转成实占 |
| 整单 dispatch | 单据 DISPATCHED | 所有分配到齐后，一次扣减暂存现存与预占 | 释放对应实占 |

在途位通过与任务的归属关系识别，承载该任务的 SKU、批次和整笔数量。发布布局只包含实体货位。暂存位可同时存放多个订单的货物，发运由每个订单的分配和任务确定对应余额及扣减量。订单 `ALLOCATED` 阶段涵盖来源预占到暂存完成，`DISPATCHED` 后原始分配保留供追溯。

`take` 和 `drop` 各写一条有完整两端的 `TRANSFER`，`dispatch` 按分配写有来源、无目标的 `DISPATCH`。流水沿用追加约束和业务键唯一约束。发运是唯一减少本链路仓内总量的操作。

## 容量与原子性

READY 和 IN_TRANSIT 任务的 Allocation 件数合计即为目标容量预留。预留与任务共用一份状态，卸货推进到 STAGED 后，事务内立即增加暂存余额。现存和预留不能同时计入同一笔货物。数据库触发器检查新任务占用、实体余额变更、布局切换三条路径。即使暂存位当前现存为零，有活动预留也不能从当前布局移除或缩减到预留以下。

服务在事务内重新检查操作者仓库角色，先锁 Warehouse 再执行读取与写入。行变更和容量触发器共同保护余额。余额、任务或订单阶段、流水、审计一起提交。仓库锁使同仓受控写入串行，目标是可验证的一致性。

业务动作由分配或任务及阶段标识。重复创建且目标相同，返回当前任务。改目标会冲突。已提交的 take、drop 或 dispatch 返回当前阶段，不重复记账。阶段业务键防止重复插入流水。重试仍重新授权。操作原因和操作者以首个成功提交为准。

## 读取与对账

库存 API 返回有载的在途余额，并将其计入全仓现存和预占。共享契约仅允许带 `transit: true` 且全量预占的正数 RELEASED 余额出现在实体布局之外。实体货位列表保持原坐标，前端通过既有 Query 快照显示已提交库存。出库列表可读 `DISPATCHED`。

现存对账对流水有记录的一端记账，发运只有负向过账。预占对账按阶段把分配映射到来源、在途或暂存。它同时检查订单分配总量、已发运订单到齐、在途实物归属，以及暂存实占加预留的容量上限。集成脚本在 PostgreSQL 重启后的同一快照中执行这些核对。

Day 10 的调用入口是内部领域服务。上架、机器人执行、取消、故障恢复和用户发运入口交给后续阶段。本次履行已成立的 Day 9 预占，批次到期不自动撤销搬运或预占。
