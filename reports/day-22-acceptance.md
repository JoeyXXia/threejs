## 最小改动与五个验收条件

三个审查组：①纯多车提案/分配与单测/固定场景；②PostgreSQL 检查点、唯一 claim、Nest 批次 runner、旧单车兼容、对账和真实库测试；③授权快照契约、Query/R3F 五车与等待展示、浏览器证据/文档。只复用原技术栈，不做 Day 23 资源许可或真实设备。

1. 同一领域任务不能被两个车/客户端领取，一车只能有一个 active claim，同车匹配重试不重置路径。
2. 三至五车集中比较下一步，禁止同格/edge swap，保守拒绝进入他车本 tick 起始占格，idle/完成/ERROR 车不透明。
3. 等待原因、阻挡车与等待 tick 可观察，无碰撞但不能完成时保持真实等待。
4. 所有接受车位、phase、载荷、claim、取放库存/流水、检查点和事件同事务，重复/过期提案拒绝，失败整批回滚，重启后能对账。
5. 实际授权 API/页面呈现五车、三台不同车分别真实上架；并发任务保留在途或等待，刷新不重置归属，viewer 只读与跨空间隔离。

设计、状态权威及事务边界见 [ADR 0013](../docs/adr/0013-persistent-fleet-coordination.md)。仍由 PostgreSQL 决定业务真相；前端不以动画完成改库存，也不外推未知下一步。

## 已覆盖的核心和事务反例

- 13 个 fleet 纯单测含 648 组 2×2 三车合法提案穷举、同目标竞争/等待排序、edge swap、保守跟随、停车/ERROR 占格、五个同时活动任务、序列化和不可变提案。
- 双独立 Prisma 客户端竞争同一任务，只能一个成功；数据库唯一索引/触发器拒绝转领、重复 claim、忙车第二活动任务，失败创建不留下领域任务。
- 真实五车各有任务，逐 tick 验证占格，观察等待；跨 scope、viewer、伪造 actor 和非法车数拒绝。
- take 时注入 `FLEET_TICK` 事件失败，余额、全车位/phase、claim、流水与水位逐项回滚；原提案成功一次后重放拒绝，租约接管递增 epoch 并拒绝旧 owner。取货后撤销权限停止批次，载荷和在途货物保留。
- 三台不同车辆顺序经 QC 放行/上架完成，产生 6 条真实取放流水，现存 65、预占 0；不是前端假车或手改数据库。
- 另外保留三车共享 QC 同时执行的反例：对向时保持真实等待及在途库存，不宣称该并发样例全部完成。五车并发出库同一暂存服务点也可能被完成停车车阻挡；不为“跑完”偷偷将车辆移走。

## 本轮失败与修正记录

早间纯核心的初轮失败定位到分配时漏存已设 approach route 的 simulation，已修正且完整复验。实际接入中静态近邻停车可挡住单车出发，改为互不相邻停车格，并在规划时避开其他车当前格/已知终点（不是永久墙或 Day 23 资源锁）。类型检查发现 R3F 颜色数组可能 undefined，增加明确 fallback。

原先“三车共享 QC 并发必全部完成”的用例假设超过保守协调承诺，真实运行捕获对向等待。没有删除此反例：将其固定为等待/载荷守恒用例，另增三车顺序完成上架用例验证业务链路。没有添加动态重规划、通道许可或隐藏状态改写来掩盖死锁。

浏览器首轮已跑到 viewer，但测试误以为 `fieldset.isDisabled()` 能判断原生 disabled 继承，导致断言失败；实际快照中的子控件均已禁用。改为核对真实提交按钮的 `isDisabled()` 与 API 的 VIEWER 角色，**重新新建整个 QA 库完整复验**，不是略过失败步骤或继续使用已执行过的库存夹具。首轮部分结果不计通过。另补旧布局切换拒绝测试，防止重置位置/电量，随后完整 136 项集成回归通过。

开发浏览器初始未登录 `/auth/me` 401 是会话检查，最终脚本页面 0 console errors；仍有依赖 `THREE.Clock` 弃用警告，未在本日扩范围升级。没有新增 fleet 专项 API SIGKILL 验收；本日直接独立客户端接管/旧 owner fencing 和真实数据库重启已测，旧单车 API kill 回归仍通过，二者不混称。
