# Day27 验收：五车进程退出、租约接管与库存唯一过账

日期：2026-11-20（Asia/Shanghai）。基线 Day26 `a15d948679334f182a7f694a55d272578368bc5a`。需求、文件与复验命令见 [Day27 日志](../docs/devlog/day-27.md)。此报告区分进程实验、数据库重启回归与未测试边界。

## 实验设计

- 固定 `demo-v1` 合成布局和车队初始化 seed 42，五台软件车。robot-1 出库，robot-2 上架；后者在前者卸货阶段加入，保证真正存在两个活动 claim 的卸货切点。其他三车占格有效但不接单。取货服务格与出库服务格配置为独立单容量工作站。
- 每个 runner 是独立 Node 子进程和 Prisma 连接。测试 IPC 只控制何时调用现有 `FleetService` 以及已准备提案何时提交；不启动 HTTP 服务，不向生产 API 加入测试入口。不用 `onModuleDestroy` 假装退出，不写短租约或篡改位姿、claim、库存。收到真实退出通知后比较退出前后数据库快照。
- 认领之前是未发送 assign 的边界；认领之后是事务已提交且子进程返回后。取放之前是已计算但尚未提交的真实提案；取放之后是事务已提交且子进程返回后。活租约拒绝、自然接管与旧提案 409 单独在两个子进程都活着时验证。
- 每个已提交 FLEET_TICK 验证格子唯一、相邻步或原地、不进入另一车辆起始格、不穿静态墙，两个工作站许可各与实际占位一致；对齐提交 tick、连续 seq、归属、取放记录和库存重算。

## 实测

五车用例于 **2026-11-20T01:53:06.997Z** 写出实测证据，六个边界均观察到子进程关闭，Node 在 Windows 报告终止信号为 SIGKILL。进程退出前后的持久快照均一致。

| 强停位置 | 最后已提交 tick / epoch / 水位 | 退出时归属与占位 | 接管与首个新提交 |
| --- | --- | --- | --- |
| 发认领命令前 | 0 / 0 / 4 | 无 claim | 新进程正常认领 |
| 认领提交后 | 0 / 0 / 6 | robot-1 活动、空载 | 新进程重试返回原 claim；随后开始推进 |
| 取货提交前 | 29 / 2 / 35 | robot-1 空载并占取货站 | 从 tick 29 / epoch 3 接管；首提交 tick 30 |
| 取货提交后 | 30 / 3 / 37 | robot-1 载货并占取货站 | 从 tick 30 / epoch 4 接管；首提交 tick 31 |
| 卸货提交前 | 48 / 4 / 60 | 两个活动 claim，robot-1 载货并占出库站 | 从 tick 48 / epoch 5 接管；首提交 tick 49 |
| 卸货提交后 | 49 / 5 / 62 | robot-1 归属关闭、已卸货但仍占出库站；robot-2 活动 | 从 tick 49 / epoch 6 接管；首提交 tick 50 |

在取货前还保留了原 epoch 1 的活进程：其租约有效时，第二进程没有取得提案；自然到期后第二进程在 tick 29 取得 epoch 2，原进程尝试提交得到 **409**，持久快照不变。epoch 2 随后在尚未提交取货前被强停，未把准备动作记成提交。

最终 **tick 77 / 水位 92**；两个原 claim 完成并关闭，出库和上架各一次取、一次放，共 **4 条唯一搬运流水**；逐条核对 **77 个提交 tick** 的格、步长、墙和 permit，事件连续，仓库库存对账一致。另三台车保持真实占格。运行记录原始 JSON 仅留本地。

最终 `pnpm check` 通过；`pnpm test:unit` **128/128**（simulation 55、web 73）；`pnpm test:integration` **156/156**（Node 57、Jest 99），无失败。三套隔离数据库真实停止并重启后，库存、预占、事件连续性和检查点对账一致。未新增浏览器测试，因为本日变更只涉及服务层进程验收。

## 不外推的结论

这是应用服务层进程退出验收，不是整个 Nest HTTP API 的新五车端到端浏览器实验，也不是在数据库事务正执行 SQL 时 kill、断电、网络分区或负载压力试验。认领前没有发送事务，不宣称模拟认领事务中崩溃。任务有计划地重叠，不保证任意同时派单都取得进展或不存在死锁。PostgreSQL 重启是既有 harness 的另一段，不与进程中断混作一次组合故障。无运行时代码、框架、依赖、部署或标签变更；不处理 Day28。
