# Day40 验收 — Runner、数据库与 Socket 同步故障矩阵

日期：2026-11-28（Asia/Shanghai），基线 `1fcf629`。

## 可观察验收

1. **T11**：真实 PostgreSQL 停在取货已写但未提交时；断库后两个 runner 都不能确认新步，重启后库存、事件、检查点和回放帧没有半成品。
2. **T11**：第二 runner 从旧水位接管并增加 epoch，拒绝旧提案，原任务取放各一次。既有 API 进程被杀与自主接管用例仍通过。
3. **T12**：在首快照已获取但未送达时有新真实提交；漏包和重复包通过 HTTP 补缺，受控 410 后重新无游标订阅，并显示新完整快照；浏览器断网时不静默画成实时，连回追平。
4. **T14**：A 迟到的真实快照不覆盖已切换的跨空间 B 仓；会话撤销后清除仓库数据，历史访问被拒绝；真实 ACL 撤销与错误仓订阅仍由后端集成复验。

## 实测证据

- **14:01（上海时间），本地 Chrome/T12**：首快照已取到 seq 0 时，另一授权客户端提交到 seq 2；旧快照送达后同步追平。代理丢弃 seq 3、重复送入 seq 4，真实 HTTP 历史响应 200 且包含缺失的 seq 3。第二轮丢 seq 5、重复 seq 6，浏览器侧注入 HTTP 410，随后恰有 1 次无游标重订阅。断网期间保留旧确认值，恢复后追平 seq 8、预占 4 件。
- **T14**：切到 B 后，释放 A 的真实旧响应（seq 8）；Playwright 成功送达该响应，B 仍是 seq 0、预占 0，A 的预占 4 未显示。独立客户端注销当前测试会话后，页面清空仓库数据并回到登录，历史请求返回 401。
- **14:06，PostgreSQL/T11**：事务内部已看到 tick 18 和 1 条取货流水，独立连接仍只看到 tick 17、seq 21。测试集群从开始关停到恢复可用用时 5,365 ms（完全停止到可用 3,334 ms，含实验等待及重启）；中断提交失败为 `P1017`，离线期间两个 runner 的操作分别返回 `P1001`、`P1017`。恢复后，余额、事件、回放帧、审计、任务和检查点与故障前一致。第二 runner 从 tick 17 接管，epoch 1→2；旧提案返回 409。原任务到 tick 47、seq 53 完成，取放各一条、序号连续、对账一致。
- 调试时，PostgreSQL 已重启但观察连接第一次读仍收到 `P1017`。验收因此主动回收隔离连接池再比较恢复数据，未重置 runner 对象、身份或旧提案，也不把此测试算成「旧连接无缝复用」。
- `pnpm check`、最终 lint 和 `git diff --check` 通过。150 项单测与 172 项默认集成（Node 73、Jest 99）通过；新增断库步骤在 Node/Jest 计数之外单独通过。4 个隔离 PostgreSQL 库重启后对账一致。两项可选 Redis 故障回归未启用。

## 范围

数据库中断是真停测试进程，浏览器的丢包、重复包、410 和断网是有界故障注入，不等于生产网络事件；410 的真实后端拒绝由既有 Day30 用例验证。没有测生产 RTO、跨节点容错或吞吐。全部场景都使用隔离仓库及既有软件机器人。
