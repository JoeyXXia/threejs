# 合成布局与期初库存来源

`demo-v1.json` 为本项目自行编写的合成地图，不来自真实仓库、设备或外部资产。它是 seed 的输入，不是浏览器库存来源；运行时 API 从 PostgreSQL 读取。

- 地图 30 × 20，cellSize=1 米，外缘原点 (0,0)，世界 Y 向上；格心映射沿用 ADR 0001。
- 6 个区域：入库、质检、储存、拣货、出库、充电。除货架投影外均按地面可通行处理，不模拟工作站实体碰撞。
- 2 组货架，每组占地 1 × 3、2 层、层间高 1.5 米。每层沿深度 3 个业务货位，共 12 个储存位；每位容量 40 件。地面服务点在货架左侧，层间共享服务格；不代表机器人具有实际举升能力。
- 另有 5 个工作站货位，总计 17 个业务货位。充电位置不放 seed 库存；容量 1 仅为当前模型字段，并非已实现机器人充电容量调度。
- 两个演示仓库各复制一份布局，空间、仓库、货位、SKU、批次 ID 相互隔离。ID 由 seed 中稳定命名键确定；位置保存在版本内，货位业务 ID 可跨版本复用。
- 每仓两个合成 SKU，各一批 B01，单位为整数件。前 10 个储存位依次放 1–10 件、交替 SKU-A / SKU-B，均 RELEASED；质检区有 SKU-A / B01 的 HOLD 7 件。因此期初现存 62，已放行未预占 55，待检 7，预占 0。批次示例到期日为 2030-01-01。

以上是样本规则；实际执行后应查询数据库和 `pnpm reconcile` 验证，不能仅凭此文件声称已入账。seed 在仓库行锁下同事务写入余额和 OPENING 流水，用业务唯一键防止重复初始化；失败时全部回滚。反复 seed 保留已有密码、仓库资料、布局和期初流水，不是运行时重置命令。
